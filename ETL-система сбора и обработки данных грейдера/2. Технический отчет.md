# Технический отчёт
## ETL-система сбора и обработки данных грейдера

### 1. Архитектура системы

Система разработана на Python и состоит из шести классов и главной функции `main()`.

| Компонент | Назначение |
|---|---|
| `Logger` | Логирование и удаление старых файлов |
| `APIClient` | Получение данных через REST API |
| `DataProcessor` | Парсинг и валидация записей |
| `DatabaseManager` | Загрузка данных в PostgreSQL |
| `ReportGenerator` | Расчёт метрик и выгрузка в Google Sheets |
| `NotificationService` | Отправка email-отчёта |
| `main()` | Управление ETL-процессом |

### 2. Класс Logger

**Назначение:** ведение логов выполнения программы и удаление устаревших файлов.

Основные методы:
- `setup_logging()` — создаёт каталог, настраивает логгер и файловый обработчик.
- `delete_old_files()` — удаляет файлы старше установленного срока хранения.

Ключевой фрагмент настройки логирования:

```python
self.logger = logging.getLogger("ETL")
self.logger.setLevel(logging.INFO)

handler = logging.FileHandler(
    f"{self.log_dir}/log_{datetime.now().date()}.txt",
    encoding="utf-8"
)
```

Логи сохраняются в отдельные файлы с датой запуска. Срок хранения задаётся через `.env`.

### 3. Класс APIClient

**Назначение:** получение исходных данных об активности студентов через REST API грейдера.

Основной метод — `fetch_data(start, end)`. Он формирует GET-запрос с параметрами клиента и временным диапазоном, проверяет ответ и возвращает список записей.

Ключевой фрагмент:

```python
response = requests.get(
    self.api_url,
    params=params,
    timeout=120
)

response.raise_for_status()
data = response.json()

if not isinstance(data, list):
    raise ValueError("API вернул данные не в формате списка.")
```

Для обработки временных сбоев предусмотрены три попытки запроса с паузой в 5 секунд. Тайм-аут составляет 120 секунд.

### 4. Класс DataProcessor

**Назначение:** преобразование исходных записей и проверка их корректности.

Основные методы:

- `parse()` — извлекает необходимые поля, разбирает `passback_params` и преобразует дату.
- `validate_record()` — проверяет обязательные поля и типы данных.

Пример извлечения параметров:

```python
parsed_dict = ast.literal_eval(
    record.get("passback_params")
)

parsed_record = {
    "user_id": record.get("lti_user_id"),
    "oauth_consumer_key": parsed_dict.get("oauth_consumer_key"),
    "lis_result_sourcedid": parsed_dict.get("lis_result_sourcedid"),
    "lis_outcome_service_url": parsed_dict.get("lis_outcome_service_url"),
    "is_correct": record.get("is_correct"),
    "attempt_type": record.get("attempt_type")
}
```

Дата события преобразуется в `datetime` для дальнейшей обработки и сохранения в PostgreSQL.

В `main()` реализована обработка записей по отдельности: корректные добавляются в итоговый набор, некорректные пропускаются и учитываются в `skipped_records`.

### 5. Класс DatabaseManager

**Назначение:** подключение к PostgreSQL и сохранение обработанных данных в таблицу `grades`.

Основные методы:
- `insert_records()` — пакетная загрузка записей.
- `close()` — закрытие соединения с базой данных.

Для загрузки используется `executemany()`:

```python
cursor.executemany(
    """
    INSERT INTO grades (
        user_id,
        oauth_consumer_key,
        lis_result_sourcedid,
        lis_outcome_service_url,
        is_correct,
        attempt_type,
        created_at
    )
    VALUES (%s, %s, %s, %s, %s, %s, %s)
    """,
    records_to_insert
)

self.conn.commit()
```

После успешной загрузки изменения фиксируются через `commit()`. При ошибке выполняется `rollback()`.

### 6. Класс ReportGenerator

**Назначение:** расчёт ежедневных показателей и передача результатов в Google Sheets.

Основные методы:
- `aggregate_daily_metrics()` — рассчитывает аналитические показатели.
- `export_to_sheets()` — добавляет результаты в Google Sheets.

Рассчитываются следующие метрики:

| Метрика | Описание |
|---|---|
| `attempts_total` | Общее количество попыток |
| `DAU` | Количество уникальных пользователей |
| `submits_correct` | Количество успешных отправок |
| `submits_incorrect` | Количество неуспешных отправок |
| `submits_total` | Общее количество отправок |
| `runs` | Количество запусков кода |

Пример расчёта успешных отправок:

```python
metrics["submits_correct"] = sum(
    1 for record in records
    if record["attempt_type"] == "submit"
    and record["is_correct"] == 1
)
```

### 7. Класс NotificationService

**Назначение:** формирование и отправка email-отчёта после завершения обработки данных.

Основные методы:
- `generate_email()` — формирует текст письма с датой и рассчитанными метриками.
- `send_email()` — выполняет подключение к SMTP-серверу и отправляет сообщение.

Для отправки используется защищённое SSL-соединение:

```python
with smtplib.SMTP_SSL(
    smtp_server,
    port,
    context=ssl.create_default_context()
) as server:
    server.login(sender_email, password)
    server.send_message(msg)
```

В письмо включаются основные показатели, ссылка на Google Sheets и информация о хранении логов.

### 8. Главная функция main()

**Назначение:** последовательное выполнение всех этапов ETL-процесса.

В функции создаются объекты классов, определяется период запроса, запускается обработка данных и выполняется выгрузка отчёта.

Для API используется дата, отстоящая от текущей на два календарных года:

```python
api_date = datetime.today() - relativedelta(years=2)

START = api_date.strftime("%Y-%m-%d 00:00:00.000000")
END = api_date.strftime("%Y-%m-%d 23:59:59.999999")
```

После получения данных записи проходят парсинг и валидацию. Затем корректные данные загружаются в PostgreSQL, по ним рассчитываются метрики, которые передаются в Google Sheets и email.

Соединение с базой данных закрывается в блоке `finally`, в том числе при возникновении ошибки.

### 9. Последовательность ETL-процесса

| Этап | Компонент | Результат |
|---|---|---|
| Extract | `APIClient` | Получение данных из REST API |
| Transform | `DataProcessor` | Преобразование и валидация записей |
| Load | `DatabaseManager` | Сохранение данных в PostgreSQL |
| Aggregate | `ReportGenerator` | Расчёт аналитических метрик |
| Export | `ReportGenerator` | Выгрузка показателей в Google Sheets |
| Notification | `NotificationService` | Отправка email-отчёта |
| Logging | `Logger` | Фиксация выполнения и ошибок |

### 10. Результат реализации

Разработана ETL-система, автоматизирующая сбор, обработку и хранение данных грейдера. Реализованы расчёт шести аналитических показателей, выгрузка отчётности в Google Sheets, логирование и отправка email-уведомлений.

Полный исходный код проекта представлен в репозитории GitHub.
