# Паспорт проекта

## ETL-система сбора и обработки данных грейдера

### 1. Описание бизнеса

Андекс Грейдер — образовательная платформа, на которой студенты изучают программирование и выполняют практические задания. Для проверки решений используется встроенный онлайн-редактор кода, который фиксирует попытки отправки заданий и результаты их проверки.

Собираемые данные позволяют отслеживать активность студентов, оценивать результаты выполнения заданий и анализировать ход обучения.

### 2. Бизнес-задача

Необходимо автоматизировать сбор и обработку данных грейдера, поскольку отсутствие удобного доступа к агрегированной информации затрудняет регулярный мониторинг активности и успеваемости студентов.

Ручное получение и обработка данных требуют времени и не позволяют оперативно формировать актуальную отчётность.

### 3. Актуальность проекта

Анализ учебной активности помогает оценивать вовлечённость студентов, отслеживать динамику выполнения заданий и выявлять возможные трудности в обучении.

Автоматизация сбора и обработки данных позволяет сократить ручной труд, снизить вероятность ошибок и обеспечить регулярное получение аналитических показателей.

### 4. Цель проекта

Разработать автоматизированную ETL-систему для сбора, проверки, хранения и обработки данных об использовании грейдера с последующим формированием аналитической отчётности в Google Sheets.

### 5. Задачи проекта

1. Получить данные об активности студентов через REST API грейдера.
2. Извлечь необходимые параметры из полученных записей.
3. Выполнить преобразование и проверку данных.
4. Организовать хранение обработанной информации в PostgreSQL.
5. Рассчитать ежедневные показатели активности и результатов выполнения заданий.
6. Автоматизировать выгрузку метрик в Google Sheets.
7. Реализовать логирование выполнения программы и обработку ошибок.
8. Настроить отправку email-уведомлений о завершении работы системы.

### 6. Источники

Основной источник данных — REST API онлайн-редактора кода (грейдера).

Система получает информацию о попытках выполнения заданий, включая:

- `user_id` — идентификатор студента;
- `attempt_type` — тип действия или попытки;
- `is_correct` — результат проверки решения;
- `created_at` — дата и время события;
- `oauth_consumer_key`, `lis_result_sourcedid`, `lis_outcome_service_url` — дополнительные параметры интеграции LTI.

### 7. Технологический стек и инструменты

| Технология | Назначение |
|---|---|
| Python | Разработка ETL-системы |
| Requests | Получение данных через REST API |
| PostgreSQL | Хранение обработанных данных |
| psycopg2 | Подключение и работа с базой данных |
| Google Sheets API | Передача аналитических данных |
| gspread | Работа с Google Sheets |
| smtplib, ssl | Отправка email-уведомлений |
| logging | Ведение логов |
| python-dotenv | Хранение конфигурации и настроек |

### 8. Структура решения

Система состоит из нескольких взаимосвязанных модулей:

1. **APIClient** — отправляет запросы к REST API и получает исходные данные.
2. **DataProcessor** — извлекает параметры, преобразует типы данных и проверяет корректность записей.
3. **DatabaseManager** — обеспечивает подключение к PostgreSQL и сохранение обработанных данных.
4. **Logger** — фиксирует этапы выполнения ETL-процесса и возникающие ошибки, а также управляет хранением лог-файлов.
5. **ReportGenerator** — рассчитывает ежедневные метрики и выгружает результаты в Google Sheets.
6. **NotificationService** — отправляет email-уведомление после завершения обработки.

Работа системы организована последовательно: получение данных → обработка и проверка → загрузка в базу данных → расчёт метрик → выгрузка отчёта → отправка уведомления.

### 9. Результаты проекта

В рамках проекта реализованы основные этапы ETL-процесса:

- получение данных через REST API;
- извлечение и валидация параметров;
- загрузка информации в PostgreSQL;
- расчёт ежедневных аналитических показателей;
- выгрузка результатов в Google Sheets;
- логирование работы программы;
- email-уведомления о завершении процесса.

В отчёт включены показатели `attempts_total`, `submits_total`, `submits_correct`, `submits_incorrect`, `DAU` и `runs`.

### 10. Практическая ценность

Разработанная система упрощает регулярный сбор информации об учебной активности и предоставляет централизованные данные для анализа.

Сформированные показатели могут использоваться для:

- мониторинга активности студентов;
- оценки результатов выполнения практических заданий;
- отслеживания динамики учебной активности;
- выявления заданий и периодов, в которых возникают сложности.

Автоматизированная отчётность позволяет получать данные без необходимости выполнять сбор и расчёты вручную.

### 11. Итог

Разработана ETL-система на Python, обеспечивающая автоматизированный сбор, обработку и передачу данных грейдера. Решение объединяет REST API, PostgreSQL и Google Sheets, позволяя формировать регулярную аналитическую отчётность об активности и результатах студентов.
