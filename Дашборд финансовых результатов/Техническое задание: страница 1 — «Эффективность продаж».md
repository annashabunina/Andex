## 1. Назначение вкладки

Вкладка «Эффективность продаж» предназначена для анализа динамики продаж и оценки финансовых результатов розничной сети за 2024–2025 годы.

Дашборд объединяет ключевые показатели эффективности (KPI), фильтры, динамические параметры и аналитические визуализации.

Основная цель — предоставить пользователю возможность оценивать результаты продаж, отслеживать изменения выручки и прибыли, сравнивать показатели между годами и выявлять сезонные закономерности.

## 2. На какие вопросы отвечает вкладка

С помощью данной страницы пользователь может получить ответы на следующие вопросы:

1. Какова общая выручка розничной сети за выбранный период?
2. Как изменяются выручка и валовая прибыль по месяцам?
3. Как меняется выбранный показатель относительно предыдущего периода?
4. Как соотносятся результаты продаж за 2024 и 2025 годы?
5. Как формируется накопительная выручка с начала каждого года?
6. Какие месяцы обеспечивают наибольшую долю годовой выручки?
7. Как изменяется средний чек?
8. Какое количество чеков формируется за выбранный период?
9. Какова оценочная валовая прибыль и валовая маржа?
10. Наблюдаются ли сезонные колебания продаж?

## 3. Описание вкладки

На данной странице представлен анализ динамики продаж розничной сети за 2024–2025 годы. Оцените ключевые показатели эффективности: выручку, валовую прибыль, средний чек и количество продаж. Изучите изменения показателей по месяцам и годам, сравните результаты периодов, проанализируйте накопительную выручку и вклад каждого месяца в годовой оборот.

**Параметр 1. Показатель**

Тип: выпадающий список.

Назначение: выбор метрики, динамику которой необходимо исследовать.

Варианты:
- Выручка;
- Валовая прибыль;
- Количество чеков;
- Количество проданных товаров;
- Средний чек.

При изменении значения параметра график должен перестраиваться и отображать выбранный показатель.

**Параметр 2. Окно скользящего среднего**

Тип: числовой параметр.

**Параметр 3. Период группировки**

Тип: выпадающий список.

Текущее значение: Месяц.

Варианты:
- День;
- Месяц;
- Квартал;
- Год.

Назначение: изменение временной детализации графика «Динамика показателей».

При изменении параметра данные должны группироваться в соответствии с выбранным временным интервалом.

## 5. Ключевые показатели эффективности (KPI)

В верхней части страницы размещены пять карточек с основными показателями эффективности продаж.

### 5.1. Выручка

**Назначение:** отображение общей суммы продаж розничной сети за выбранный период.

Формула:

```sql
SUM([сумма_строки])
```

Единица измерения: рубли.

### 5.2. Валовая прибыль

**Назначение:** оценка разницы между выручкой и себестоимостью реализованных товаров.

Формула:

```sql
SUM([сумма_строки])
-
SUM([количество] * [цена_закупки_руб])
```

Единица измерения: рубли.

**Ограничение:** показатель является оценочным, поскольку используется текущая закупочная цена из справочника товаров, а не историческая себестоимость на дату продажи.

### 5.3. Средний чек

**Назначение:** отображение средней суммы одной покупки.

Формула:

```sql
SUM([сумма_строки]) / COUNTD([id_чека])
```

Единица измерения: рубли.

Для расчёта используется количество уникальных чеков, поскольку один чек может содержать несколько товарных позиций.

### 5.4. Количество чеков

**Назначение:** отображение количества уникальных покупок за выбранный период.

Формула:

```sql
COUNTD([id_чека])
```

Единица измерения: чеки.

### 5.5. Валовая маржа

**Назначение:** отображение доли оценочной валовой прибыли в общей выручке.

Формула:

```sql
(
    SUM([сумма_строки])
    -
    SUM([количество] * [цена_закупки_руб])
)
/
SUM([сумма_строки])
```

Единица измерения: проценты.

**Ограничение:** показатель является оценочным из-за использования текущей закупочной цены товаров.

## 6. Описание аналитических графиков

### 6.1. «Динамика показателей»

**Тип:** линейная диаграмма с двумя линиями.

**Назначение:** анализ изменения выбранного показателя во времени, выявление тенденций и сглаживание краткосрочных колебаний.

**Настройки:**

| Элемент | Настройка |
|---|---|
| Ось X | Дата с выбранной группировкой |
| Ось Y | Выбранный показатель |
| Первая линия | Фактическое значение показателя |
| Вторая линия | Скользящее среднее |
| Дополнительные подписи | Изменение относительно предыдущего периода |
| Сортировка | Дата по возрастанию |

**Используемые параметры:**
- Показатель;
- Окно скользящего среднего;
- Период группировки.

**Аналитические задачи:**
- выявление периодов роста и снижения показателей;
- определение сезонных колебаний;
- анализ краткосрочных изменений;
- сглаживание колебаний с помощью скользящего среднего;
- оценка общего направления динамики.

**Продвинутые функции:**

1. `MAVG()` — оконная функция скользящего среднего. Используется для сглаживания фактических значений показателя.

Пример для пяти предшествующих периодов:

```sql
MAVG(
    SUM([сумма_строки]),
    5
    ORDER BY [Месяц]
)
```

Если параметр окна задаётся динамически, вместо числа используется соответствующий параметр с учётом того, что `MAVG` принимает число предшествующих строк.

2. `LAG()` — оконная функция получения значения предыдущего периода.

Пример:

```sql
LAG(
    SUM([сумма_строки])
    ORDER BY [Месяц]
)
```

Может использоваться для расчёта процентного изменения относительно предыдущего периода.

Формула процентного изменения:

```text
(Текущее значение - Предыдущее значение)
/
Предыдущее значение × 100%
```

3. `DATETRUNC()` — функция группировки даты по выбранному временному интервалу.

4. `CASE` — условная логика выбора показателя в зависимости от значения параметра.

### 6.2. «Сравнение показателей за 2024 и 2025 годы»

**Тип:** сгруппированная столбчатая диаграмма.

**Назначение:** сравнение результатов продаж за два года по одинаковым календарным месяцам.

**Настройки:**

| Элемент | Настройка |
|---|---|
| Ось X | Название месяца |
| Ось Y | Выбранный показатель |
| Цвет | Год (2024 и 2025) |
| Тип столбцов | С группировкой, без накопления |
| Сортировка | По номеру месяца по возрастанию |

**Аналитические задачи:**
- сравнение одинаковых месяцев двух лет;
- выявление месяцев с наибольшим ростом или снижением;
- оценка сезонности продаж;
- определение периодов с существенными различиями между годами.

**Используемые функции:**

`YEAR()` — получение года из даты.

```sql
YEAR([дата_время])
```

`MONTH()` — получение номера месяца.

```sql
MONTH([дата_время])
```

`CASE` — преобразование номера месяца в название.

Пример:

```sql
CASE
    WHEN MONTH([дата_время]) = 1 THEN 'Январь'
    WHEN MONTH([дата_время]) = 2 THEN 'Февраль'
    WHEN MONTH([дата_время]) = 3 THEN 'Март'
    WHEN MONTH([дата_время]) = 4 THEN 'Апрель'
    WHEN MONTH([дата_время]) = 5 THEN 'Май'
    WHEN MONTH([дата_время]) = 6 THEN 'Июнь'
    WHEN MONTH([дата_время]) = 7 THEN 'Июль'
    WHEN MONTH([дата_время]) = 8 THEN 'Август'
    WHEN MONTH([дата_время]) = 9 THEN 'Сентябрь'
    WHEN MONTH([дата_время]) = 10 THEN 'Октябрь'
    WHEN MONTH([дата_время]) = 11 THEN 'Ноябрь'
    WHEN MONTH([дата_время]) = 12 THEN 'Декабрь'
END
```

Месяцы должны сортироваться по отдельному числовому полю `Месяц`, а не по алфавиту.

### 6.3. «Накопительная выручка по годам»

**Тип:** линейная диаграмма.

**Назначение:** отображение нарастающего итога выручки с начала каждого календарного года.

**Настройки:**

| Элемент | Настройка |
|---|---|
| Ось X | Месяц |
| Ось Y | Накопительная выручка |
| Цвет | Год (2024 и 2025) |
| Сортировка | По месяцу по возрастанию |

**Логика расчёта:**

Для каждого месяца рассчитывается сумма выручки за текущий месяц и все предыдущие месяцы соответствующего года.

В январе каждого года накопление начинается заново. В декабре значение соответствует общей выручке за год.

Формула:

```sql
RSUM(
    SUM([сумма_строки])
    WITHIN [Год]
    ORDER BY [Месяц]
)
```

**Аналитические задачи:**
- оценка темпа формирования годовой выручки;
- сравнение накопительных результатов 2024 и 2025 годов;
- определение периода, в котором один год опережает другой;
- оценка выполнения годового плана при наличии плановых значений.

**Продвинутая функция:**

`RSUM()` — оконная функция накопительной суммы.

Дополнительно применяются:
- `WITHIN [Год]` — разделение накопления по годам;
- `ORDER BY [Месяц]` — определение последовательности расчёта.

### 6.4. «Выручка и валовая прибыль»

**Тип:** комбинированная диаграмма (столбцы и линия).

**Назначение:** сопоставление месячной выручки и оценочной валовой прибыли.

**Настройки:**

| Элемент | Настройка |
|---|---|
| Ось X | Месяц |
| Столбцы | Выручка |
| Линия | Оценочная валовая прибыль |
| Единица измерения | Рубли |

Формула выручки:

```sql
SUM([сумма_строки])
```

Формула оценочной валовой прибыли:

```sql
SUM([сумма_строки])
-
SUM([количество] * [цена_закупки_руб])
```

**Аналитические задачи:**
- сравнение динамики выручки и валовой прибыли;
- определение месяцев с наиболее высокой прибылью;
- выявление периодов, когда изменение прибыли отличается от изменения выручки;
- оценка финансового результата продаж в разрезе месяцев.

**Используемые функции:**
- `SUM()` — агрегирование выручки и оценочной себестоимости;
- арифметические операции — расчёт разницы между выручкой и себестоимостью.

**Ограничение:** валовая прибыль является оценочной, поскольку используется текущая закупочная цена товаров.

### 6.5. «Доля периода в году»

**Тип:** столбчатая диаграмма.

**Назначение:** отображение доли выручки каждого месяца в общей годовой выручке.

**Настройки:**

| Элемент | Настройка |
|---|---|
| Ось X | Месяц |
| Ось Y | Доля месячной выручки в годовой выручке |
| Цвет | Год (2024 и 2025) |
| Формат | Проценты |
| Сортировка | По номеру месяца по возрастанию |

Логика расчёта:

Доля месяца определяется как отношение выручки за месяц к общей выручке соответствующего года.

Формула:

```sql
SUM([сумма_строки])
/
SUM(
    SUM([сумма_строки])
    WITHIN [Год]
)
```

Результат форматируется как процентное значение.

**Аналитические задачи:**
- определение месяцев, формирующих наибольшую долю годовой выручки;
- выявление сезонности продаж;
- сравнение распределения выручки между месяцами в 2024 и 2025 годах;
- определение периодов с повышенной и пониженной покупательской активностью.

**Продвинутые функции и конструкции:**

- Вложенная агрегация `SUM(SUM(...))` — расчёт годового итога на уровне месячных значений.
- `WITHIN [Год]` — разделение расчёта по годам.
- Деление агрегированных показателей — вычисление доли месячной выручки в годовом обороте.

**Контроль:** сумма долей всех месяцев полного года должна составлять 100%.

Важно: фильтр даты может влиять на знаменатель расчёта. Если пользователь выбирает только отдельный месяц, необходимо обеспечить сохранение полного годового итога в знаменателе. Для этого может применяться `BEFORE FILTER BY` с полем даты.

## 7. Продвинутые функции Yandex DataLens

В проекте используются не только стандартные агрегаты, но и инструменты для выполнения оконных расчётов, динамической аналитики и сложной группировки показателей.

### 7.1. Оконные функции

| Функция | Назначение | Применение |
|---|---|---|
| `RSUM()` | Накопительная сумма | Накопительная выручка по годам |
| `MAVG()` | Скользящее среднее | Сглаживание динамики показателей |
| `LAG()` | Получение значения предыдущей строки окна | Сравнение с предыдущим периодом |

Оконные функции позволяют выполнять расчёты по последовательности строк с учётом порядка сортировки и группировки.

### 7.2. Вложенные агрегации и оконные расчёты

Пример:

```sql
SUM(
    SUM([сумма_строки])
    WITHIN [Год]
)
```

Назначение:
- расчёт годового итога на основе месячных значений;
- определение доли месяца в годовой выручке;
- сравнение показателей на разных уровнях агрегации.

### 7.3. Условная логика

`CASE` применяется для:
- выбора показателя в зависимости от параметра;
- преобразования номера месяца в его название;
- реализации нескольких вариантов расчёта в одном вычисляемом поле.

### 7.4. Работа с датами

| Функция | Назначение |
|---|---|
| `YEAR()` | Получение года из даты |
| `MONTH()` | Получение номера месяца |
| `DATETRUNC()` | Группировка даты по выбранному периоду |

Эти функции обеспечивают временную детализацию и сопоставимость результатов по календарным периодам.

### 7.5. Уникальная агрегация

`COUNTD()` используется для подсчёта уникальных чеков.

Применение:
- расчёт количества чеков;
- расчёт среднего чека;
- исключение повторного подсчёта одного чека при наличии нескольких товарных строк.

### 7.6. Управление порядком вычислений

`BEFORE FILTER BY` — модификатор оконных вычислений, позволяющий рассчитать показатель до применения фильтрации по указанным полям.

Может применяться для сохранения полного годового знаменателя при расчёте доли месяца, даже если отображаемые данные ограничены фильтром даты.

Применение должно быть проверено на конкретной конфигурации фильтров и графика.

### 7.7. Параметры и динамические вычисления

В дашборде применяются параметры:
- выбор анализируемого показателя;
- изменение окна скользящего среднего;
- переключение периода группировки.

Это позволяет использовать одну визуализацию для нескольких аналитических сценариев вместо создания отдельных графиков для каждой метрики и временной детализации.

### 7.8. LOD-функции

Функции `FIXED`, `INCLUDE`, `EXCLUDE` относятся к инструментам изменения уровня детализации вычислений.

В текущей реализации первой вкладки их использование по представленным скриншотам не подтверждено, поэтому они не включаются в перечень фактически применённых функций.

## 8. Методологические требования и ограничения

1. Выручка рассчитывается как сумма поля `сумма_строки`.
2. Необходимо проверить, что скидка уже учтена в `сумма_строки`, чтобы не вычитать её повторно.
3. Количество чеков рассчитывается через `COUNTD([id_чека])`, поскольку один чек может содержать несколько товарных строк.
4. Валовая прибыль и валовая маржа являются оценочными при использовании текущей закупочной цены из справочника товаров.
5. Для достоверного расчёта исторической валовой прибыли необходима себестоимость товара на дату продажи.
6. Покупки без карты лояльности не должны исключаться из расчёта общей выручки и количества чеков.
7. При расчёте доли месяца в годовой выручке знаменатель должен учитывать полный год.
8. Для оконных функций необходимо корректно задавать группировку и сортировку.
9. При отсутствии данных за выбранный период визуализации не должны показывать некорректные значения.
10. При использовании нескольких фильтров необходимо проверять порядок их применения относительно оконных вычислений.

---

## 9. Требования к оформлению

- Денежные показатели отображаются в рублях.
- Процентные показатели отображаются в процентном формате.
- Для сравнения годов используются единые цвета на всех графиках.
- Месяцы располагаются в календарном порядке.
- Заголовки графиков должны отражать содержание визуализации.
- При наведении на элементы графиков должны отображаться значения показателей и соответствующий период.
- KPI-карточки должны иметь единый стиль оформления.
- Фильтры и параметры должны быть визуально отделены от аналитических графиков.
- Необходимо обеспечить читаемость подписей, легенд и осей.

## 10. Критерии приёмки

**Фильтры и параметры:**
- Работают фильтры даты, региона, магазина и года.
- Параметр «Показатель» изменяет метрику на графике динамики.
- Изменение окна скользящего среднего перестраивает сглаженную линию.
- Изменение периода группировки меняет временную детализацию.

**KPI:**
- Отображаются все пять ключевых показателей.
- Средний чек рассчитывается на основе уникальных чеков.
- Валовая прибыль и маржа имеют корректную оценочную методологию.

**Графики:**
- Динамика показателей отображает фактическое значение и скользящее среднее.
- Сравнение годов показывает одинаковые месяцы рядом.
- Накопительная выручка начинается заново для каждого года.
- График выручки и валовой прибыли отображает оба показателя.
- Доля периода рассчитывается относительно полного годового оборота.

**Расчёты:**
- Сумма долей месяцев за полный год составляет 100%.
- Накопительная выручка за декабрь совпадает с годовой выручкой.
- Все графики корректно реагируют на фильтры.
- Оконные функции используют правильную группировку и сортировку.
- Визуализации не содержат ошибок агрегации.

## 11. Итог

Вкладка «Эффективность продаж» объединяет базовую и продвинутую аналитику розничной сети.

В рамках реализации используются:

- KPI и агрегированные показатели;
- уникальная агрегация чеков;
- динамический выбор метрик через параметры;
- условная логика `CASE`;
- работа с датами через `YEAR`, `MONTH`, `DATETRUNC`;
- оконная функция `RSUM` для накопительной выручки;
- оконная функция `MAVG` для скользящего среднего;
- оконная функция `LAG` для анализа предыдущих периодов;
- вложенные агрегации;
- группировка оконных расчётов через `WITHIN`;
- управление порядком вычислений через `BEFORE FILTER BY` при необходимости.

Дашборд обеспечивает комплексный анализ динамики продаж, позволяет оценивать финансовые результаты и выявлять закономерности изменения выручки за 2024–2025 годы.
